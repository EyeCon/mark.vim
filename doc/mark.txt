*mark.txt*    mark.nvim: Highlight several words in different colors simultaneously.

Author:      Lua port for Neovim 0.12+.
Based on the Vimscript plugin mark.vim (vimscript #2666) by Ingo Karkat, a
continuation of vimscript #1238 by Yuheng Xie.

DESCRIPTION                                              *mark.nvim* *mark*

This plugin adds mappings and a |:Mark| command to highlight several words in
different colors simultaneously, similar to 'hlsearch' and the built-in
|star| command: while browsing a big program file, highlight multiple
identifiers in parallel to make it easier to trace the source code.

- Uses matchadd() per window; no clashes with syntax highlighting, jumps
  behave like the built-in search (counts, wrap messages, jumplist, folds).
- The number of mark groups equals the number of configured colors; mark
  group N is highlighted with color N.
- Mark sets can be persisted globally in named slots and activated
  automatically per |filetype|.

REQUIREMENTS

Neovim 0.12 or later.

CONFIGURATION                                        *mark-configuration*

                                                        *mark-setup()*
`require('mark').setup({...})`

                                                        *mark-colors*
`colors` ~
  Explicit list of colors. This is the primary configuration: the number of
  mark groups is the length of this table, and mark group N uses colors[N].
  Each entry is either
  - a string: shorthand for a background color, or
  - a table of |nvim_set_hl()| attributes (e.g. { bg = ..., fg = ..., bold = true }).
>
    require('mark').setup({
      colors = {
        '#8CCBEA',                        -- background only
        { bg = '#A4E57E', fg = 'black' }, -- full attributes
        { ctermbg = 'Yellow', ctermfg = 'Black', bg = '#FFDB72', fg = 'Black' },
      },
    })
<

                                                        *mark-palette*
`palette` ~
  Used when `colors` is nil: one of 'original' (default, 9 colors - the
  original plugin's 6 defaults plus a teal and a dark gray from its other
  palettes), 'extended', 'maximum'. Switch at runtime with
  `:Mark palette {name}`.

                                                        *mark-ignorecase*
`ignorecase` ~
  nil (default) = follow &ignorecase; true/false override it for marks. An
  explicit case-sensitive atom \C inside a pattern always wins. 'smartcase'
  is deliberately ignored, like in the original plugin.

`history` ~
  true (default): add set patterns to the search history.

`group_jump_keys` ~
  Define <k1>..<kN> and <C-k1>..<C-kN> direct group jump mappings for groups
  1..N (default 9).

                                                        *mark-persistence*
`persistence` ~
  Marks are stored globally (not per file) in a JSON file with named slots.
  - enabled (true): master switch
  - auto_save (true): save the current set into the "default" slot after
    every change
  - auto_load (false): load the "default" slot on startup
  - path: vim.fn.stdpath('data') .. '/mark.json' by default

                                                        *mark-filetype-marks*
`filetype_marks` ~
  Map filetypes to mark sets; the mapped set is activated when a buffer of
  that filetype is used. A string value names a stored slot (see |:Mark-load|),
  a table value is an inline pattern list. Buffers without a mapping leave
  the current set untouched. Manual marks are always global.
>
    require('mark').setup({
      colors = { ... },
      filetype_marks = {
        lua = 'LUA',                       -- stored slot
        python = { 'def \\s\\+\\k\\+' },   -- inline patterns
      },
    })
<

                                                        *mark-keymaps*
`keymaps` ~
  Configure or disable (false) default mappings. All <Plug>(Mark*) mappings
  are always defined for custom mappings.
>
    keymaps = {
      mark = '<leader>m',        -- {Visual} too: mark word / selection
      regex = '<leader>r',       -- {Visual} too: mark by regexp input
      iwhite = false,            -- {Visual}: whitespace-indifferent selection
      clear = '<leader>n',       -- clear mark under cursor (or disable all)
      all_clear = false,         -- clear all marks
      toggle = false,            -- enable/disable display of all marks
      current_next = '<leader>*',
      current_prev = '<leader>#',
      any_next = '<leader>/',
      any_prev = '<leader>?',
      next = '*',                -- falls back to builtin * when not on a mark
      prev = '#',
      or_cur_next = false,       -- always current mark (no last-search memory)
      or_cur_prev = false,
      or_any_next = false,       -- always any mark
      or_any_prev = false,
      group_next = false,        -- search group [count] (queries when omitted)
      group_prev = false,
    }
<
  With `group_jump_keys = N`, <k1>..<kN> jump to mark group N forwards and
  <C-k1>..<C-kN> backwards.

COMMANDS                                                *mark-commands*

                                                        *:Mark-set*
:[N]Mark set[!] {pattern}
    Toggle {pattern}: clear it if already marked, else set it in the next
    free group (cycling when all groups are in use). With [N], add/subtract
    {pattern} as an alternative in group N. With [!], an already marked
    pattern is kept (no toggle-off) and made the current mark.

                                                        *:Mark-list*
:Mark list
    Print all mark groups, their pattern(s) and markers: ">" marks the next
    group to be used, "/" the current search mark.

                                                        *:Mark-clear*
:Mark clear [N|all]
    Clear the mark under the cursor (when it exists, else disable all
    marks), clear group [N], or clear everything with "all".

                                                        *:Mark-toggle*
:Mark toggle
    Enable/disable the display of all marks; the patterns are kept (like
    |:nohlsearch| for search highlighting).

                                                        *:Mark-save*
:Mark save [slot]
    Store the current mark set in [slot] (default "default") in the JSON
    persistence file.

                                                        *:Mark-load*
:Mark load [slot]
    Load the mark set from [slot], replacing the current set (marks of the
    current set that are not in the slot are lost).

:Mark load! [slot]
    Merge the mark set from [slot] into the current set instead of
    replacing it: patterns are added as alternatives of the corresponding
    group, already present alternatives are skipped, and the display state
    is kept. Patterns beyond the number of groups are ignored.

                                                        *:Mark-palette*
:Mark palette {name}
    Switch to a built-in palette ('original', 'extended', 'maximum') at
    runtime; the number of groups is adjusted, already set patterns are kept
    where possible.

MAPPINGS                                                *mark-mappings*

The defaults are listed under |mark-keymaps|; the <Plug> mappings for custom
configuration:
    <Plug>(MarkSet)             n,x
    <Plug>(MarkRegex)           n,x
    <Plug>(MarkIWhiteSet)       x
    <Plug>(MarkClear)           n
    <Plug>(MarkAllClear)        n
    <Plug>(MarkToggle)          n
    <Plug>(MarkSearchCurrentNext/Prev)      n
    <Plug>(MarkSearchAnyNext/Prev)          n
    <Plug>(MarkSearchNext/Prev)             n
    <Plug>(MarkSearchOrCurNext/Prev)        n
    <Plug>(MarkSearchOrAnyNext/Prev)        n
    <Plug>(MarkSearchGroupNext/Prev)        n
    <Plug>(MarkSearchGroup{N}Next/Prev)     n

Behavior notes:
- The searches add the original position to the jumplist and open folds,
  like the built-in [/?*#nN].
- With 'nowrapscan', the search stops at the end/start with an error; with
  'wrapscan', a wrap message is echoed.
- <k1>..<k9> and <C-k1>..<C-k9> (with group_jump_keys) jump to a particular
  mark group directly.

PUBLIC API                                          *mark-public-api*

require('mark').groups()               number of mark groups
require('mark').pattern([index])       pattern of group [index] / current
require('mark').set_palette(name)      switch palette (like |:Mark-palette|)
